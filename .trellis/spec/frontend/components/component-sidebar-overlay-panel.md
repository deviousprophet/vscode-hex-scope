# Component Spec — Overlay Panel

## Scope / Trigger

Owns `src/webview/components/sidebar/overlayPanel/overlayPanel.ts` (orchestrator), its extracted render modules (`cPreview.ts`, `binaryView.ts`, `editorFields.ts`, `valueFormat.ts`, `rowRenderer.ts`), `overlayInstancesModel.ts` and `overlayPanel.css`: the sidebar Overlay panel — both tracks (pins/instances + types/editor). The component owns all panel markup, expansion state, bit-field allocation toggle, editor draft state, pin add/edit state, field-value menus, pointer follow/create, and the bit-layout toggle. It never reads/writes the `S` global and never posts provider messages: data is pushed via setters, byte reads go through the injected `readByte` accessor, and actions report via callbacks.

Host (`hexViewer.ts`) owns: `S` state, type/instance persistence (`saveTypes`/`saveTypeInstances`), selection, endian, bit-field allocation, hex-view highlight, and jumps.

## Layout

```text
src/webview/components/sidebar/overlayPanel/
    overlayPanel.ts         orchestrator: mount/render/setData/setEndian/setBitFieldAllocation/setSelection/setTabActive/resetViewState
    cPreview.ts      C-preview token/line builders + renderTypeCPreview/hydrateTypePreviews
    binaryView.ts    bit-span / binary rendering helpers
    editorFields.ts  editor field-row markup helpers
    valueFormat.ts   decoded value formatting + copy-text helpers (owns ColType/OverlayRenderCtx)
    rowRenderer.ts   decoded row/group renderers + pointer renderers
    overlayInstancesModel.ts     pure pin-model helpers (makeTypeInstance, withEditedTypeInstance, upsertPointerTypeInstance, ...)
    overlayPanel.css        all panel rules (moved verbatim from the legacy panel stylesheet)
src/webview/hexViewer.ts   host wiring (panel descriptor, applyTypes/applyPins/applyOverlayState, selectRangeHost, highlight)
src/test/webview/components/sidebar/overlayPanel/overlayPanel.test.ts   (mocha + jsdom)
```

The extracted render modules are free functions over a narrow `OverlayRenderCtx` (types/pins/endian/bit-field allocation/show-hidden/field-value types/default value type/readByte + expansion and bit-range sets); `overlayPanel.ts` keeps the `OverlayPanel` class as the orchestrator and exposes thin delegating methods so its call sites stay stable. None of the five modules import `S`, `state.ts`, `postProviderMessage`, `memory/memoryData`, or `rerender`.

Panel shell (`sidebar/sidebar.ts`) and shared `.sb-section`/`.sb-body`/`.sb-badge`/`.sb-empty` stay in `sidebar/sidebar.ts`/`sidebar/sidebar.css`. `core/overlay/overlayCodec.ts` is pure and shared; mixed-endian overrides extend it with per-field/per-type `endian`/`allocation` resolution (threaded effective values, pointer-global exception, `DecodedField.endian`/`allocation` resolved indicators) — the panel consumes the resolved row values for badges and passes the same effective values into bit-unit binary rendering.

## Contract

```typescript
interface OverlayCallbacks {
    readByte: (addr: number) => number | undefined;        // required — host memory adapter
    onTypesChange?: (types: TypeDef[]) => void;      // save/delete type
    onPinsChange?: (pins: TypeInstance[]) => void;            // add/edit/delete/pointer-create pin
    onStateChange?: (types: TypeDef[], pins: TypeInstance[]) => void;  // both at once (e.g. delete type cascades instances)
    onSelectRange?: (start: number, count: number) => void; // instance row/range selection → host S.selStart/S.selEnd + jumpTo + inspector
    onHighlightHex?: (addrs: number[], cls: string) => void; // hover/array-sep class on hex rows
    onClearHighlightHex?: (cls: string) => void;
    onBitAllocationChange?: (bitAllocation: BitFieldAllocation) => void; // global LSB/MSB toggle
    onShowHiddenFieldsChange?: (showHiddenFields: boolean) => void;      // global show-hidden toggle
    onRefreshAddresses?: (pinId?: string) => void;    // re-run every script address source
    onOpenScript?: (scriptPath: string) => void;      // open the selected address script
    onRequestScripts?: () => void;                    // ask the host for the role-tagged script list
    onCreateScript?: (role: ScriptRole) => void;      // empty address/size picker → host posts createScript
    onOpenScriptsFolder?: () => void;                 // empty address/size picker → host posts openScriptsFolder
}

class OverlayPanel {
    constructor(cb: OverlayCallbacks);
    mount(root: HTMLElement): void;                          // renders both tracks; idempotent
    render(): void;                                          // was renderStructPins; re-renders from pushed state
    setData(types: TypeDef[], pins: TypeInstance[]): void;  // host pushes S.types/S.typeInstances
    setEndian(endian: 'le' | 'be'): void;                    // decode source
    setBitFieldAllocation(alloc: BitFieldAllocation): void;  // 'lsb' | 'msb'
    setShowHiddenFields(show: boolean): void;                // instance-view hidden filter
    setScripts(scripts: OverlayScriptInfo[], trusted: boolean): void; // role-tagged source picker
    clearAddressResolutions(): void;                         // document close / profile switch
    markAddressesStale(generation: number): void;            // generation changed; no decode
    markAddressesResolving(pinIds: readonly string[]): void; // batch in flight
    applyAddressResults(results: InstanceAddressResult[], generation: number): void;
    clearParamResolutions(): void;                           // transient size values
    markParamsStale(generation: number): void;
    markParamsResolving(entries: readonly { pinId: string; param: string }[]): void;
    applyParamResults(results: InstanceParamResult[], generation: number): void;
    paramResolution(pinId: string, param: string): ParamResolution | undefined;
    resolvedParamValues(pinId: string, generation: number): ReadonlyMap<string, number>;
    paramBlockReason(pinId: string): string | undefined;
    setSelection(start: number | null): void;                // was onSelectionChangeForStruct
    setTabActive(active: boolean): void;                     // host pushes sidebarTab==='overlay'
    resetViewState(): void;                                  // was resetStructViewState
}
```

## Rules

- Component holds only UI/transient state (expansion Sets, `_fieldValTypes`, `_activeTypeAddr`, add/edit-form flags, `_applyTypeId`, bit-range selection, `_tabActive`). Persistent/domain state lives in the host.
- Reads no `S`, writes no `S`; data pushed via setters; actions report via callbacks. `readByte` is injected (host passes `getByte` from `memory/memoryData`) so byte access stays host-owned — the component must NOT import `memory/memoryData`.
- Type/instance mutations report `onTypesChange`/`onPinsChange`/`onStateChange`; the host syncs `S` + persists (`saveTypes`/`saveTypeInstances`). Selection → `onSelectRange`; hex-row highlight/array separators → `onHighlightHex`/`onClearHighlightHex`. The host applies them through the HexView paint seam (`memoryGrid.paintTypeHighlight`/`paintClearTypeHighlight` → `HexView.paintTypeHighlight`/`paintClearTypeHighlight`, root-scoped) — never a host `[data-addr]` DOM poke.
- The host field `S.activeStructAddr` was removed from `state.ts` (had no external push/read sites); the component keeps `_activeTypeAddr` internally.
- Markup is byte-identical to pre-refactor (same ids/classes); all CSS moved verbatim from the legacy permanent stylesheet. Untrusted text escaped with `esc()`. **DOM ids / class prefixes are frozen**: the runtime sidebar root is `#sbp-overlay`, the tab `#stab-overlay`, and the section elements `#oi-instances` / `#oi-types` (bodies `…-body`); the JSDOM **test-fixture root** is `#s-overlay` (the production root is the `#sbp-*` panel, not `#s-*`). Frozen classes are `.oe-type-default-*` and the `oi-` / `om-` / `oa-` / `oe-` / `ofe-` / `od-` families, but the `data-*` attributes that **mirror a persisted key** follow the key: `data-type-id` on the type-list action buttons (formerly `data-struct-id`) and `data-source-type-id` on decoded rows (formerly `data-source-struct-id`), with the matching `dataset.typeId` / `dataset.sourceTypeId` reads. The `create-type-ptr` field-menu command id mirrors `typeId` the same way.
  The struct-derived vocabulary was renamed to the Overlay families (internal only): `si-`→`oi-`, `se-`→`oe-`, `sfe-`→`ofe-`, `sa-`→`oa-`, `sm-`→`om-`, `sd-`→`od-`; `#s-struct-pins`→`#s-overlay` (test-fixture root), `#s-struct`→`#s-types` (types-list comment id), sidebar panel id `'struct'`→`'overlay'` (⇒ `#stab-overlay`/`#sbp-overlay`), `.se-struct-default-*`→`.oe-type-default-*`, `.sa-struct-sel`→`.oa-type-sel`, `.struct-field-row`→`.field-row`, `.struct-addr-pfx`→`.addr-pfx`, `.struct-h`→`.type-h`, `.struct-arr-sep`→`.type-arr-sep`, `data-se-view`→`data-oe-view` (`dataset.oeView`). Put the `oi-`/`om-` family prefix on the section ids too: `SidebarSections(root, 'oi', …)` (section element ids `oi-instances`/`oi-types`, bodies `oi-instances-body`/`oi-types-body`). The persisted/legacy `struct*` identifiers (`structs.json`, `structPins`, `structId`, `refStructId`, `sourceStructId`) and the `type: 'struct'` kind vocabulary keep the word.
  The Types-list chip keeps the `.od-kind` base class and gains additive `.od-kind-struct` / `.od-kind-bitfield` / `.od-kind-enum` accent modifiers (also applied to the editor's `.oe-kind-badge`); the list filter bar is `.od-tools` with `#om-filter` / `#om-kind-filter`. No existing ids/classes are renamed for these features.
- The named-type kind badge is one shared primitive: `.od-kind` / `.oe-kind-badge` share the badge rule at the 10px type floor, differing only by layout modifiers (`.od-kind` fills its fixed 56px grid track — `justify-self: stretch; width: 100%; box-sizing: border-box`, so every chip is the same width — in the type list; `.oe-kind-badge` = `justify-self:start` in the editor default row). `.oi-chip` and record-view tags remain the documented 9px dense-mark exception in `css-guidelines.md`.
- Pin model helpers stay pure and unit-tested (`overlayInstancesModel.ts`); no DOM, no `S`.
- Script-address resolution state is component-owned and transient: `_addressResolutions` (`Map<pinId, AddressResolution>`) never leaves the panel and is pruned on `setData`/delete. Script-size state is the same: `_paramResolutions` (`Map<"pinId\0param", ParamResolution>`) is transient, pruned when the instance/source/manual override disappears, and exposed only through the focused `paramResolution` / `resolvedParamValues` / `paramBlockReason` accessors. The host owns scheduling and the batched `resolveInstanceAddresses` / `resolveInstanceParams` messages; the panel's `mark*` / `apply*` methods update the maps and refresh **only** the instances list (`refreshInstances`, never a full `render()`) so an open Types editor draft and form input survive. The panel never posts provider messages; refresh/open/script-list actions go through callbacks.

## Behaviour

- Pins track — script addresses: the add/edit form gains an address-source selector (`#oa-addr-source`: Fixed address / From script); the fixed `#oa-addr` input hides in script mode and the script row (`#oa-script-sel` + `#oa-script-open`) lists only `roles.includes('address')` scripts (the authored path stays visible as `(not found)`), disables From script for pointer-created instances, and shows `#oa-script-untrusted` when the workspace is untrusted. An empty address picker adds `.oa-script-empty-row` with **Create instance address script** (`data-create-script="address"` → `onCreateScript`) and **Open scripts folder** (`data-open-scripts-folder` → `onOpenScriptsFolder`); an empty size picker adds one `.oa-params-empty-row` with the `size` variants. Both rows hide when `setScripts` pushes a matching script or when the mode leaves script. Confirm requires a selected script in script mode and stores `addressSource` (never a resolved address); `addr` keeps the last authored/active address (or `0`). The Instances header carries `#oi-refresh-addrs-btn` ("Refresh addresses", disabled without dynamic instances) and a dynamic card carries `.act-btn-addr-refresh`; both report via `onRefreshAddresses`. Dynamic cards render `resolving…` / resolved `0x… · NB` / `stale` / the error message, a `.oi-script-chip` (path tooltip), disable expansion, and suppress decoded rows unless `status === 'resolved'`.
- Pins track: add-pin form (hex address, type picker), instance cards (expand/collapse `›` chevron, always-visible Edit/View-type/Delete actions, delete w/ inline confirm), decoded rows incl. scalar/array/struct/bitfield/pointer rows + pointer follow/create; bit-layout LSB/MSB toggle reporting each explicit switch via `onBitAllocationChange` (host persists `saveBitAllocation` into the bound profile; the host push via `setBitFieldAllocation` stays authoritative on refresh, e.g. profile switch/external edit). For a templated selected type the add/edit form renders `#oa-params` — one `.oa-param-row` (`data-param-name`, `.oa-param-source` Manual/From script, `.oa-param-inp`, `.oa-param-script` filtered to `@script size`, `.oa-param-open`) per declared `TypeParam`, pre-filled from the edited instance's `paramValues` then the parameter default. Confirm validates (`validateInstanceParamConfig` + integer parsing) and shows `#oa-param-error` instead of creating a pin on zero/negative/fractional/missing values, a script mode without a selected script, or a manual value with a source. Applied values/sources are stored as `paramValues` / `paramSources` (declared keys only). The Instances header also carries a global **Show hidden** toggle button (`#oi-show-hidden-btn`; matching the bit-layout `.compact-tabs` control, its `active` class and `aria-pressed` state mirror the flag) that reports via `onShowHiddenFieldsChange` (host persists `saveShowHiddenFields`; `setShowHiddenFields` is authoritative on refresh). While it is off (default), decoded groups whose declared field resolves `hidden === true` are filtered out at the decode-to-render seam (`renderTypeFieldGroups` + `renderNestedTypeGroup` via `resolveTypeFieldByPath`), dropping a hidden container's whole subtree; toggling it re-renders the instances in place without reopening the editor. The Instances `＋ Add` header button is disabled when no types exist (tooltip "No types defined").
- Types track: type list, **kind chooser**, and a per-kind editor. The `＋ Add` header button sets `_choosingKind` and replaces the Types body with a three-tile picker (`#om-kind-picker`, `.om-kind-tile[data-kind]` = `struct` / `bitfield` / `enum`, `#om-kind-cancel`); each tile seeds that kind's draft and clears `_choosingKind`, Cancel returns to the list creating nothing, and the kind is immutable after creation. `editorHtml(draft, existing)` dispatches on `draft.kind`: `'bitfield'` → `bitFieldDefEditorHtml`, `'enum'` → `enumDefEditorHtml`, else `typeEditorHtml`. `＋ Add` is disabled while an editor or the picker is open; there is no in-body "New type" button and no `←` back button.
- Types track — list rows: every kind renders one kind chip (`.od-kind` + `.od-kind-<kind>` modifier) with the sentence-case label `Struct` / `Bit-field` / `Enum` (matching the kind-chooser tiles; no uppercase transform). Per-kind accents are component-local in `overlayPanel.css`: `.od-kind-struct` (`--high-color` tint), `.od-kind-bitfield` (`--warn` tint), `.od-kind-enum` (`#c586c0` tint); the meta stays monochrome. Row order is `kind chip → name → meta → actions`. Meta is one line: struct = `N field(s) · X B` (`typeByteSize(def, all)` — thread the full defs pool for nested sizes), bit-field = `<base> · used/total bits` (Σ child `bitWidth` / `fieldByteSize(base) * 8`; never `typeByteSize` on a bit-field def — it returns 0), enum = `<base> · N entries`. The list is sorted kind-grouped then case-insensitive name A-Z (`sortTypeDefs` on a **copy**); the shared `allTypes()` order and every picker/dropdown keep the stored (creation) order.
  The row is a **four-cell grid** shared by every row (kind | name | meta | actions); the actions are two unwrapped 18px buttons, so they occupy a trailing `auto auto` pair — five tracks in all: `56px minmax(0, 1fr) minmax(0, max-content) auto auto`. The leading kind track is fixed and `.od-kind` fills it (`justify-self: stretch; width: 100%; box-sizing: border-box`, centered text), so every badge renders at the same width (56px, which fits the widest label `Bit-field` at ≈46px) and the chips form one aligned column. The meta track is **content-sized** (`max-content`), so the info renders in full; `text-overflow: ellipsis` remains only as the overflow safety-valve. `.od-name` is the only flexible cell (`minmax(0, 1fr)`), so it absorbs slack and ellipsizes first. Every ellipsized cell carries a `title` with its full text (`.od-name` ← `def.name`, `.od-meta` ← the meta string), and the row itself carries `title="<name> — <meta>"` so the info stays discoverable when hidden. Below 300px the name would be squeezed, so the info is hidden **and its track removed**; at ≥300px it is shown. This is a container query on the list (`#om-list { container-type: inline-size }` → `@container (max-width: 299px) { .od-row { grid-template-columns: 56px minmax(0, 1fr) auto auto } .od-meta { display: none } }`) — the sidebar width is not the viewport width. Untrusted names are `esc()`-escaped in both the text and the `title` attributes.
- Types track — list filter bar: above `#om-list`, `.od-tools` carries a name search (`#om-filter`, case-insensitive trimmed substring) and a kind filter (`#om-kind-filter`: `All`/`Struct`/`Bit-field`/`Enum`). Both live on the panel as transient view state (`_typeFilter`, `_typeKindFilter`), compose with the sort, and are never persisted or posted to the host. Filter events rebuild only `#om-list` (`refreshTypeList`, which re-wires the row actions) so the search input keeps focus and the editor/body is untouched. Empty states are distinct: no types at all → "No types defined yet."; a filter with no matches → "No types match." `resetViewState` clears both filters. Both controls share one explicit 20px control box (`.od-tools .od-filter` / `.od-tools .od-kind-filter`: `height:20px`, `box-sizing:border-box`, `line-height:1`, `--font-ui` at 10px) so the native select — a replaced control whose UA metrics are taller — matches the text input's height; the native select arrow is kept (no `appearance: none`), the input keeps `flex:1; min-width:0`, and the select keeps `flex-shrink:0; max-width:92px`.
- The kind chip in the shared bit-field/enum editor shell (`.oe-kind-badge`) uses the same `typeKindLabel` + `.od-kind-<kind>` accent mapping, keeping the list and form in agreement.
- Types track — pure-struct editor: name/packed/endian + the field grid (type, pointer, name, per-field endian, **alloc**, **hide**, array, move, delete; **9-column** grid, no `Bits` column, no per-field bit toggle, no child bit rows). The `Alloc` column renders a per-field `Alloc` select **only** on a reusable bit-field-reference row; every other row keeps a placeholder cell so the grid stays aligned. The `Hide` column is a per-field checkbox that sets `TypeField.hidden` (instance-view only; unchecked writes no key). Above the field grid sits the **Parameters** section (`#oe-params-list`, `+ Add parameter` `#oe-param-add`): one `.ofe-param-row` per `TypeParam` with a name input (`.ofe-param-name`), an optional default input (`.ofe-param-default`), move up/down, and delete (`.ofe-param-del`). Adding seeds `COUNT`/default 2; a name blur sanitizes the identifier and rewrites every `countParam` reference in the same draft; deleting a referenced parameter is blocked with an inline `#oe-param-error` naming the field; adding/deleting the first/last parameter toggles the form's `has-params` class (wider `[ ]` track) in place. The array cell's third state is the `.ofe-count-param` select (`literal` + one option per declared parameter): selecting a parameter sets `countParam` and hides the literal count input (`.has-param`), `count` is kept mirrored to the parameter default (or 1) on save, and toggling the array off clears the parameter binding. When the type declares params, the field header/rows/type-default row use the wider array track via `.oe-form.has-params` (the 9-column contract is otherwise unchanged). The editor has an `Edit` / `Preview` segmented tab bar (`.oe-tabs.compact-tabs`, `role=tablist`) at the top: the form (name, type default, field header, `#oe-fields`, Add Field, inline error, Save/Cancel) lives in `.oe-view[data-oe-view=edit]` and the C preview in `.oe-view[data-oe-view=preview][hidden]`. Switching views is attribute-only (toggles `active`/`aria-selected` on the tabs and `hidden` on the views, ArrowLeft/ArrowRight + Enter/Space; never a re-render), so draft state and the section-body scroll position are preserved; the editor always opens on `Edit`. The preview has NO fixed `max-height` and no inner scroll — its syntax-highlighted C code flows in the section body and scrolls with it, wrapping long lines (`white-space: pre-wrap; overflow-wrap: anywhere`). Pointer declaration is a visible per-field `*` toggle button in a dedicated `Ptr` column with the per-field context-menu path ("Attach pointer"/"Clear pointer") kept as a secondary route; a `void`-typed field is pointer-active by default and cannot have pointer stripped, bit-field-reference and enum-reference rows show the button disabled, and the button active state mirrors `data-ptr`/`editorRowIsPointer`.
- Types track — reusable bit-field types: a `kind: 'bitfield'` def is listed with an `.od-kind` badge and `<baseType> · used/total bits` meta; editing it dispatches to `bitFieldDefEditorHtml`/`wireBitFieldDefEditor` (name + `#oe-base-type` unsigned width + a `.ofe-bf-child-hdr` column header (`Name · Bits · Enum · Hide`) + `#oe-bf-def-children` name/width rows, no type field grid, no nesting). Reached only through the kind chooser's **Bit-field** tile (seeded `baseType:'uint32'` + one child); the standalone `#om-add-bitfield-btn` action is removed. Each child row also carries a def-level **hidden** checkbox (`.ofe-bf-child-hidden`, `checked` from `child.hidden`) that authors `BitFieldChild.hidden` — instance-view only, so hiding a bit hides it in every type that references it; the change handler syncs the draft + refreshes the preview. The field type picker groups scalar / Struct / **Bit-field** options (`bitfield:<id>`); a bitfield-reference row blocks the pointer toggle and is the **only** row that authors a per-field `Alloc` override (usage-scoped; all other rows keep the alignment placeholder). The `+ Add bit` button (`#oe-bf-def-add`) of the bit-field form disables when the base width is fully allocated.
- Types track — enum types: a `kind: 'enum'` def is listed with the `.od-kind` badge and `<baseType> · N entries` meta; editing dispatches to `enumDefEditorHtml` + its wiring (name + `#oe-enum-base-type` unsigned width + a `.ofe-enum-entry-hdr` column header (`Name · Value`) + `#oe-enum-entries` name/value rows with `#oe-enum-add` / `.ofe-enum-del-entry` / move, inline `.oe-error` range validation that blocks Save). Reached only through the kind chooser's **Enum** tile (seeded `baseType:'uint8'` + one entry); the standalone `#om-add-enum-btn` action is removed. The field type picker adds an **Enum** optgroup (`enum:<id>`); each bit-field child row (inline and def editors) gains an optional enum picker (`.ofe-bf-child-enum`). Enum-typed fields block the pointer toggle and show no alloc override.
- Hex-view selection clears stale instance selection and syncs add/edit-form address inputs (`setSelection`); the `S.sidebarTab === 'overlay'` guard is replaced by `setTabActive`.
- Row/header click selects the corresponding byte range → `onSelectRange`; hover highlights hex rows via callback.
- Field-value context menus: sticky `View as` per row identity, `Copy as`, pointer jump/create — all report-only.
- Per-field/per-struct endian (`LE`/`BE`) overrides: the plain-type editor shows a tri-state type-level `Endian` select (`Auto`/`LE`/`BE`, `Auto` = inherited, `#oe-endian`) and a per-field `Endian` select on every row (`.ofe-endian-sel`). Controls keep a neutral background regardless of selection — no tint on explicit selections; the `Auto` option's `title` shows the inherited source (e.g. `Auto — inherits BE`). The type-level `Endian` sits in a grid-aligned `.oe-type-default-row` sharing the field grid columns: the Packed toggle sits in the Type column (shortened `packed` label, full `__attribute__((packed))` in `title`), a "type default" label fills the Name column. The pure-struct form authors **no type-level** allocation override (`#oe-alloc` is gone) and no `Bits` column; a per-field `.ofe-alloc-sel` is authored **only** on a reusable bit-field-reference row (every other row keeps an alignment placeholder cell). Legacy `allocation` values on loaded fields/defs stay intact through save and still drive decode, and the `hidden` flag is authored by the per-field `Hide` checkbox (instance-view only). Decoded rows + bit-unit parent headers still render an explicit-override chip when the effective endian/allocation differs from the global overlay (a per-field alloc is authored on bit-field-reference rows; type-level and other-field allocation values are JSON/import-only now); bit-unit chips appear only on the parent value row — bit child rows and pointer header rows never chip (pointer rows resolve the inherited field/type endian, not the global overlay, but render no chips). Value cells render with the row's resolved endian/allocation, not the global overlay. Long nested type names in the type select truncate with the full name in `title`.

## Validation & Error Matrix

| Condition | Behaviour |
|---|---|
| Empty pins, no types | "Define a type first." empty state; Instances `＋ Add` disabled |
| Empty pins, types exist | "No instances yet" empty state |
| Empty types | "No types defined yet" empty state |
| Pin address invalid/partial/overflow | Rejected (`parseTypeInstanceAddressInput` → null) |
| Struct editor invalid (name/count/type/bitfield) | Inline `oe-error`; no `onTypesChange` |
| Pointer target unmapped | `(unmapped)` status, no arrow/expansion |
| Selected range disappears after remap | Selection cleared, no stale state |
| Missing bytes | `??`; never decode as zero |

## Common Mistakes

- **Stale derived bit-field-def state after a text-edit.** The `#oe-bf-def-add` (`+ Add bit`) button's disabled state derives from the bit-field def's remaining bits (sum of child `bitWidth` vs `typeByteSize * 8`). Editing a child's width in place calls `syncEditorDraft` + `refreshEditorPreview`, but `refreshEditorPreview` only re-renders `#oe-preview` — it never rebuilds the row-set, so any control whose state is computed during the row render stays stale. Width/base-type edits must therefore call `refreshBitFieldDefAddButton` (updates the button's `disabled`/`title` in place without losing input focus). Example regression scenario: u8 def with children 3+5 (full, button disabled) → shrink the first child to 1 (total 6) → button must enable immediately, without save/reopen.
- **Re-capping array counts.** Array element count is intentionally unlimited (see `overlay-model.md`). The count input keeps only a non-digit strip; do not add `maxlength`, `slice(0, N)`, or `Math.min` back to `fieldArrayCellHtml` / the `.ofe-count-inp` handler / `readEditorArrayCount`.
- **Re-introducing inline bit-field authoring into the pure-struct form.** The pure-struct field grid is 9 columns (Type/Ptr/Name/Endian/Alloc/Hide/[ ]/move/del) and authors no bit toggle, no child bit rows, and no `Bits` column. The `Alloc` select is authored **only** on a reusable bit-field-reference row (all other rows render a placeholder cell); never restore a type-level `#oe-alloc` or a per-field alloc on non-reference rows. Inline containers load via migration → reusable types; keep decode-only support for legacy inline shapes, not editor markup.
- **Moving the bit-field/enum def-row header inside its row container.** `bitFieldChildHeaderHtml` / `enumEntryHeaderHtml` must stay a **sibling above** `#oe-bf-def-children` / `#oe-enum-entries`, never inside them: the incremental refresh (`refreshBitFieldDefRows` / `refreshEnumDefRows`) replaces that container's `innerHTML`, so a header placed inside would be silently destroyed on every add/move/delete, and the existing `.ofe-bf-child-row` / `.ofe-enum-entry-row` count queries would start matching it. The header and its rows must also keep the **same** `grid-template-columns` (one shared rule) or the labels stop lining up with their inputs.

## Anti-patterns

- `overlayPanel.ts` (or any module under `overlayPanel/`) importing `S`, `state.ts`, `postProviderMessage`, `memory/memoryData`, or `rerender`.
- Component poking `[data-addr]` hex rows directly (must use `onHighlightHex`).
- Host mutating `S.types`/`S.typeInstances` without a `setData` push.
- Global-DOM-id queries outside the component root.
- Weakening `overlayPanel.test.ts` assertions during the extraction (parity gate).
